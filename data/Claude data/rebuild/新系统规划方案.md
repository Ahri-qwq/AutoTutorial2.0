# AutoTutorial 3.0 新系统规划方案

## 一、核心设计理念

### 1.1 从脚本驱动到Claude Code驱动
**原系统问题：**
- 流程固化（step1→step2→step3→step4）
- 章节间割裂、内容重复
- 无法灵活调整流程
- 缺少审查和迭代机制

**新系统理念：**
- **Claude Code作为主控**：通过CLAUDE.md文件控制整个流程
- **流程可预测但灵活**：核心原则不变，具体步骤可调整
- **Think Aloud机制**：每步都说明思考过程
- **多轮审查机制**：内容审查→案例审查→去AI审查

---

## 三、核心流程设计

### 3.1 不需要"工作区判断"
**原因：** 我们只做一件事——生成ABACUS学术教程

**简化为：** 直接进入任务类型判断

---

### 3.2 任务类型判断
Claude Code首先判断任务类型：

**类型A：新建教程（完整流程）**
- 输入：主题 + 可选案例
- 流程：7步完整流程

**类型B：基于案例的教程（案例驱动）**
- 输入：主题 + 必需案例
- 流程：7步流程 + 强化案例检查

**类型C：修改已有教程**
- 输入：原文 + 修改需求
- 流程：读取→理解→修改→审查

---

### 3.3 完整7步流程（新建教程）

#### **Step 0: 任务初始化**
**Claude Code执行：**
1. 创建工作目录：`_workspace/YYYYMMDD_HHMMSS_主题/`
2. 保存任务简报到 `00_brief.md`
   - 主题
   - 是否有案例（如有，案例路径）
   - 是否案例驱动
   - 特殊要求

**输出：** `00_brief.md`

---

#### **Step 1: 知识调研与案例解析**
**Claude Code执行：**

**1.1 RAG知识检索**
- 使用retriever.py从知识库检索相关文档
- 检索策略：
  - 主查询：`"{主题} 物理原理 参数设置 计算流程"`（top_k=10）
  - 补充查询：`"{主题} 常见问题 注意事项"`（top_k=5）
- 保存检索结果到 `01_research.md`

**1.2 案例解析（如果有案例）**
- 使用case_parser.py解析案例文件
- 提取：
  - 文件结构（INPUT、STRU、KPT等）
  - 关键参数及其值
  - 计算流程
  - 特殊设置
- 保存解析结果到 `01_research.md`（追加）

**1.3 风格参考学习**
- 读取 `_reference_materials/style_references/` 中的3-5篇参考文章
- 提取：
  - 开头方式（如何引入主题）
  - 结构偏好（章节组织方式）
  - 语言特征（专业但易懂）
  - 案例呈现方式（代码块格式、参数说明方式）
- 保存风格总结到 `01_research.md`（追加）

**Think Aloud：**
```
我正在进行知识调研：
1. 从知识库检索到15个相关文档，覆盖了物理原理、参数设置、常见问题
2. 案例解析发现：用户使用了特殊的应力计算设置（cal_stress=1, stress_thr=0.01）
3. 参考文章的风格特点：开头先讲物理背景，然后逐步深入到参数设置，最后给出完整案例
```

**输出：** `01_research.md`（包含检索结果、案例解析、风格总结）

---

#### **Step 2: 大纲讨论（不直接写！）**
**Claude Code执行：**

**2.1 生成3个大纲方案**
基于调研结果，生成3个不同的大纲方案：

**方案A：理论优先型**
- 第一章：物理原理深度解析
- 第二章：ABACUS实现方法
- 第三章：参数设置详解
- 第四章：案例实战
- 预计字数：5000字

**方案B：实战优先型**
- 第一章：快速上手案例
- 第二章：理论背景补充
- 第三章：参数调优技巧
- 预计字数：3500字

**方案C：案例驱动型（如果有案例）**
- 第一章：案例背景与目标
- 第二章：案例文件结构解析
- 第三章：关键参数详解
- 第四章：运行与结果分析
- 第五章：扩展与变体
- 预计字数：4000字

**2.2 等待用户选择**
保存3个方案到 `02_outline.md`，**不自动选择**

**Think Aloud：**
```
我提供了3个大纲方案：
- 方案A适合理论基础较好的读者
- 方案B适合想快速上手的读者
- 方案C适合你提供了案例的情况，可以围绕案例展开

请选择一个方案，或者告诉我需要调整的地方。
```

**输出：** `02_outline.md`（3个方案）

**用户交互：** 用户选择方案或提出修改意见

---

#### **Step 3: 撰写初稿**
**Claude Code执行：**

**3.1 基于选定大纲撰写**
- 按章节顺序撰写
- 每章独立RAG检索（双查询策略）：
  - 宏观查询：`"ABACUS {章节主题} 原理"`
  - 细节查询：`"ABACUS {章节主题} INPUT参数 示例"`
- 如果是案例驱动，每章都引用案例中的具体数据

**3.2 写作原则**
- **基于真实数据**：所有参数、数值必须来自检索结果或案例
- **保持风格一致**：参考风格总结
- **代码块完整**：包含文件名、完整参数
- **避免AI腔**：
  - ❌ "在当今科学研究中..."
  - ✅ "弹性常数计算是材料力学性质研究的基础"
  - ❌ "值得注意的是..."
  - ✅ "这里需要特别注意..."

**3.3 案例数据完整性（如果是案例驱动）**
- 案例中的所有参数必须在文中出现
- 参数值不能修改
- 文件结构必须完整呈现

**Think Aloud：**
```
我正在撰写第二章"参数设置详解"：
1. 从检索结果中找到了cal_stress参数的详细说明
2. 案例中使用的是cal_stress=1, stress_thr=0.01，我会在文中完整呈现
3. 参考文章的风格是先解释参数含义，再给出推荐值，我会遵循这个结构
```

**输出：** `03_draft.md`（完整初稿）

---

#### **Step 4: 内容审查**
**Claude Code执行：**

**4.1 逻辑审查**
- 章节间逻辑是否连贯
- 是否有重复内容
- 是否有前后矛盾

**4.2 事实审查**
- 所有参数名是否准确（对照检索结果）
- 数值是否正确
- 是否有幻觉内容

**4.3 结构审查**
- 章节长度是否合理（避免某章过长）
- 是否需要拆分或合并章节

**4.4 生成审查报告**
```markdown
# 内容审查报告

## 发现的问题
1. 第二章和第三章都提到了"应力计算"，有重复
2. 第三章中提到的参数"stress_threshold"应为"stress_thr"
3. 第四章过长（2000字），建议拆分为两章

## 修改建议
1. 将第二章的"应力计算"部分移除，统一在第三章讲解
2. 修正参数名
3. 将第四章拆分为"运行与监控"和"结果分析"两章

## 修改后的大纲
...
```

**输出：** `04_review_content.md`（审查报告 + 修改后的稿件）

---

#### **Step 5: 案例审查（如果有案例）**
**Claude Code执行：**

**5.1 案例完整性检查**
- 案例中的所有文件是否在文中提及
- 案例中的所有参数是否在文中出现
- 参数值是否与案例一致

**5.2 案例数据准确性检查**
- 对比案例原文和教程中的引用
- 检查是否有数值被修改
- 检查是否有遗漏

**5.3 生成案例审查报告**
```markdown
# 案例审查报告

## 案例完整性
✅ INPUT文件：已完整呈现
✅ STRU文件：已完整呈现
❌ KPT文件：未在文中提及

## 参数准确性
✅ cal_stress=1：正确
✅ stress_thr=0.01：正确
❌ ecutwfc=100：案例中是80，文中写错了

## 需要修改的地方
1. 补充KPT文件的说明
2. 修正ecutwfc参数值
```

**输出：** `05_review_case.md`（审查报告 + 修改后的稿件）

---

#### **Step 6: 风格审查（去AI化）**
**Claude Code执行：**

**6.1 AI腔检测**
检查并修改以下AI腔表达：
- "在当今..." → 删除
- "值得注意的是..." → "需要注意..."
- "综上所述..." → "总结一下..."
- "首先...其次...最后..." → 改为更自然的过渡

**6.2 语言风格对齐**
- 对照参考文章的语言风格
- 调整句式、用词
- 增加口语化表达（适度）

**6.3 细节打磨**
- 检查标点符号
- 拆分超过30字的长句
- 调整段落长度（避免大段文字）

**6.4 生成风格审查报告**
```markdown
# 风格审查报告

## AI腔修改
1. "在当今材料科学研究中" → "材料力学性质研究中"
2. "值得注意的是，应力计算需要..." → "应力计算需要特别注意..."

## 长句拆分
原句："弹性常数的计算基于应力-应变关系，通过对晶体施加微小应变并计算对应的应力响应，最后通过拟合应力-应变曲线得到弹性常数矩阵。"
修改为：
"弹性常数的计算基于应力-应变关系。具体方法是：对晶体施加微小应变，计算对应的应力响应，最后通过拟合应力-应变曲线得到弹性常数矩阵。"

## 风格对齐
参考文章的特点：开头简洁，直接进入主题。已调整第一章的开头。
```

**输出：** `06_review_style.md`（审查报告 + 修改后的稿件）

## 五、与原系统的对比

### 5.1 原系统（AutoTutorial 2.0）
```
用户输入 → Step1(知识预研) → Step2(大纲) → Step3(分章撰写) → Step4(组装) → 输出
```
**问题：**
- 流程固化，无法调整
- 章节间割裂
- 无审查机制
- 无用户参与

### 5.2 新系统（AutoTutorial 3.0）
```
用户输入 → 任务判断 → 调研 → 大纲讨论（等待用户） → 撰写 → 三轮审查 → 输出
```
**优势：**
- 流程灵活可调
- 用户参与决策（大纲选择）
- 多轮审查保证质量
- Think Aloud增加透明度
